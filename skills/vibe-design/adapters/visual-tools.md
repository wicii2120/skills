# Visual Tools Adapter

Load this only when image generation or a semantic visual-artifact tool is available and materially useful for brand identity, illustration, photography, composition, reference images, or direction exploration.

## 1. Decide whether a tool helps

Use generation when visual evidence reduces direction risk or supplies a needed original asset. Prefer supplied real assets when they already satisfy the purpose and rights. Skip generation when the task is primarily information architecture, component behavior, content, or accessibility.

**Gate:** Each proposed generation has a purpose, target artifact, aspect/viewport, fidelity, and production/replacement status.

## 2. Build the visual brief

Specify subject, audience/task, Design Read, composition, hierarchy, camera/material/light or illustration language, palette/type relationship, content-safe area, aspect/resolution, responsive crops, representation constraints, prohibited treatments, and intended interface placement.

For semantic design tools such as Google Stitch-style workflows, preserve a concise `DESIGN.md` or equivalent with semantic color/type/spacing roles, components, states, responsive behavior, content, motion intent, and anti-patterns. Treat generated code/artifacts as exploration input until reconciled with the portable contract and project stack.

## 3. Generate and evaluate

Generate only the images/boards/views needed by the artifact contract. Evaluate subject accuracy, composition, identity, readability, responsive crop, content safety, representation, fabrication risk, and consistency with the Design Read. Regenerate rather than hiding a failed composition with destructive cropping.

Generated references do not replace real product screenshots, verified claims, information architecture, component contracts, or accessibility requirements.

## 4. Record the asset ledger

For every output, record:

- supplied, generated, licensed, or provisional origin;
- tool/model and date when available;
- rights/attribution and production approval status;
- source prompt/brief location when retained;
- required crop/safe area and responsive variants;
- localization and representation notes;
- alternative-text/equivalent intent;
- replacement owner and deadline for provisional material.

## 5. Fallback

When the preferred visual tool is unavailable, produce an asset brief, composition diagram, crop/safe-area specification, and ledger row. Continue with real content, semantic layout, and clearly provisional slots. State which visual qualities remain unverified.

**Completion:** Tool use materially supports the design; outputs are evaluated rather than accepted blindly; provenance/rights/replacement are explicit; generated material cannot be mistaken for verified product evidence; the artifact remains implementable and accessible without depending on the tool at runtime.
